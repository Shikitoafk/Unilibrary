# Разборы университетов

Статический сайт с глубокими разборами университетов для абитуриентов из
Казахстана. Astro + контент-коллекции, деплой на Vercel.

Один университет — один `.mdx` файл. Всё остальное (главная с фильтрами,
таблица сравнения, оглавление, полоса соответствия) собирается автоматически.

## Запуск

```bash
npm install
npm run dev
```

Откроется на http://localhost:4321.

```bash
npm run build     # сборка в dist/
npm run preview   # посмотреть собранное
```

## Как устроен контент

```
src/content/universities/cornell.mdx   ← один файл = один университет
src/content.config.ts                  ← схема frontmatter (и она же валидатор)
```

`frontmatter` — это структурные данные: по ним работают фильтры на главной и
строится таблица сравнения. Схема в `content.config.ts` проверяет их при сборке,
поэтому опечатка в поле уронит билд, а не тихо сломает фильтр.

Тело файла — сам разбор. Доступные компоненты (импортировать не нужно, они
подключаются автоматически):

| Компонент | Что означает | Как выглядит |
|---|---|---|
| `<Fact>` | проверяемое утверждение | основная антиква |
| `<Interp>` | твоя интерпретация, а не факт | гротеск |
| `<Voice>` | прямая речь студента | крупная выносная цитата |
| `<Unknown>` | вопросы без ответа | мелкий приглушённый текст |
| `<Src href="...">` | первичный источник | кликабельная сноска |
| `<Src2>` | вторичный агрегатор | помечен ромбом, не кликается |
| `<Unver />` | на месте `[web:needed]` | «источник не подтверждён» |
| `<Section num id title>` | раздел разбора | заголовок + кнопка «Ссылка» |
| `<Tbl>` | обёртка таблицы | горизонтальный скролл |
| `<Xref>` | ссылка на другой разбор | выноска «Ср. с» |

Регистр высказывания несёт **гарнитура**, а не цветная плашка: читатель за
секунду отличает проверяемый факт от интерпретации автора.

### Добавить университет

1. Скопировать `src/content/universities/_template.mdx` в `<slug>.mdx`
   (slug станет адресом: `nyuad.mdx` → `/u/nyuad`).
2. Заполнить frontmatter и тело.
3. `npm run dev` — страница, карточка на главной и колонка в сравнении появятся
   сами.

Ничего больше править не нужно: списки стран и направлений для фильтров
собираются из самих разборов.

## Деплой на Vercel

Один раз:

```bash
git init
git add -A
git commit -m "Разборы университетов: первая версия"
```

Дальше создать пустой репозиторий на GitHub и запушить:

```bash
git remote add origin https://github.com/<логин>/<репозиторий>.git
git branch -M main
git push -u origin main
```

Затем на [vercel.com/new](https://vercel.com/new) импортировать этот репозиторий.
Astro определяется автоматически — команду сборки и папку вывода менять не надо
(`npm run build`, `dist`). После этого каждый `git push` в `main` выкатывает
новую версию сам.

Альтернатива без GitHub — `npx vercel` прямо из папки проекта.

## Что стоит помнить про источники

В разборах два вида сносок. Первичные (`<Src>`) кликаются и ведут на
официальные страницы. Вторичные (`<Src2>`) помечены ромбом ◇ — это блоги
приёмных консультантов и агрегаторы. Их концентрация обычно максимальна в
разделах о поступлении и деньгах, то есть там, где читатель принимает решения
о своих деньгах и годе жизни. Такие цифры стоит переподтверждать по Common Data
Set и официальному сайту приёмной комиссии до публикации.

`<Unver />` отмечает места, где в исходном исследовании стоял `[web:needed]`.

## Структура

```
src/
  components/     блоки разбора
  content/
    universities/ разборы (.mdx)
  layouts/        общий каркас страницы
  lib/format.ts   форматирование чисел и подписи
  pages/
    index.astro   главная: список + фильтры
    compare.astro таблица сравнения
    u/[slug].astro страница разбора
  styles/global.css  вся визуальная система
scripts/
  html-to-mdx.mjs   разовый конвертер старых HTML-прототипов
```
